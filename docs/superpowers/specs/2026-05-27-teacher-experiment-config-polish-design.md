# 教师端实验配置优化设计

## 背景

教师端已经具备实验库、草稿保存、构建发布、文件导入和软删除能力。当前短板是配置过程仍偏 JSON，教师编辑步骤时缺少直观流程感；导入文件到保存实验的闭环还缺少专门回归测试；“停用”在产品语义上需要更贴近用户提出的“删除实验”。

本轮继续围绕短期目标“实验配置管理”，不扩展课堂监控、成绩统计或报告管理。

## 目标

1. 教师端提供明确的删除实验入口，执行后学生端不再显示该实验。
2. 步骤配置从纯 JSON 编辑升级为可视化步骤流程编辑。
3. 步骤编辑支持新增、删除、上移、下移，并自动维持步骤编号。
4. 容器配置保留 JSON 高级编辑，但步骤 JSON 下沉为高级视图。
5. 导入 Markdown/TXT 文件生成的草稿默认保持 draft，教师确认保存或发布后才改变状态。
6. 增加后端测试覆盖“上传文件生成草稿，然后保存实验成功”的链路。
7. 通过后端测试、前端构建和浏览器验证确认教师端可用。

## 非目标

1. 不做硬删除数据库记录，历史会话、日志和报告继续保留。
2. 不在本轮实现完整 verification 可视化编辑器，保留高级 JSON 兜底。
3. 不新增前端测试框架，前端通过 TypeScript 构建和浏览器交互验证。
4. 不改变学生端实训流程。

## 推荐方案

保持现有左侧实验库和右侧配置详情布局。右侧将配置分为更清晰的流程：

- 基础信息：实验 ID、名称、镜像、目标、状态。
- 导入文档：上传文件或粘贴文本生成可编辑草稿。
- 步骤流程：以卡片形式编辑每个步骤的标题、目标、操作说明、参考命令、成功标准和 AI 提示关注点。
- 高级配置：容器 JSON 和步骤 JSON，供需要精修 verification 或依赖项时使用。
- 保存发布：保存草稿、构建镜像并发布、查看 Dockerfile 和构建日志。

## 交互设计

### 删除实验

左侧按钮文案改为“删除”。点击后弹出确认：

- 明确说明这是从教学入口删除，历史记录保留。
- 后端仍调用 DELETE 接口，将状态更新为 inactive。
- 删除后当前实验详情显示“已删除”，学生端列表不显示。

### 步骤流程编辑

步骤编辑器展示一个纵向步骤列表：

- 每个步骤卡片左侧显示步骤序号。
- 卡片内编辑标题、目标、操作说明、参考命令、成功标准、成功提示、AI 辅导关注点。
- 参考命令用每行一条命令的 textarea 编辑，保存时转成数组。
- 支持添加步骤、删除步骤、上移、下移。
- 操作后自动重新编号为 1..N。
- JSON 高级编辑仍可直接修改完整步骤数组，便于编辑 verification。

### 导入文件到创建实验

上传 Markdown/TXT 后：

- 后端生成 draft，并默认 status 为 draft。
- 前端将导入草稿载入右侧编辑器。
- 教师可以继续调整步骤流程，点击保存草稿后写入数据库。
- 测试覆盖导入结果保存成功，确保字段能被保存接口接受。

## 数据和 API

沿用现有 API：

- `POST /api/admin/experiments/import-file`：上传文件生成草稿。
- `POST /api/admin/experiments`：保存实验配置。
- `DELETE /api/admin/experiments/{experiment_id}`：软删除实验。
- `GET /api/admin/experiments`：教师端查看全部状态。
- `GET /api/experiments`：学生端只看 published 和兼容 active。

需要调整：

- `ensure_experiment_draft_defaults` 默认 status 从 active 改为 draft。
- 文件导入接口返回 draft 时包含 draft status。
- 保存接口继续接受 steps、container_spec 和基础字段。

## 错误处理

- 步骤流程编辑产生的步骤在保存前仍走统一校验。
- 删除前必须确认，删除失败保留当前编辑状态。
- 高级 JSON 解析失败时展示校验错误，不覆盖可视化编辑中的字段。
- 发布前继续要求镜像名和至少一个步骤。

## 测试策略

后端：

- 测试导入文件默认生成 draft。
- 测试导入文件返回的 draft 可以直接保存为实验。
- 保留已有删除、学生端过滤、构建发布和导入异常测试。

前端：

- `npm run build` 验证 TypeScript 和生产构建。
- 浏览器验证教师端登录、导入文件、保存实验、步骤可视化编辑、新建、复制、删除、学生端隐藏草稿和删除实验。
