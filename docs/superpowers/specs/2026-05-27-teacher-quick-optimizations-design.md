# 教师端快速优化设计

## 目标

本轮聚焦教师端短期可见收益：解释清楚 verification 判定语义，降低教师编辑验证规则的 JSON 门槛，支持 TXT 批量导入学生名单，为 AI 识别文档增加等待反馈，并让实验库和四阶段配置流程更易扫描。

## 验证规则语义

`command_match.commands` 保持“候选命令，任一匹配即可”的语义。示例 `["whoami", "id"]` 表示学生敲 `whoami` 或 `id` 都能通过该检查项。

需要全部命令时使用两类更明确规则：

- `command_sequence`：要求本步骤历史命令按顺序出现。
- `command_set`：要求本步骤历史命令覆盖全部命令，顺序不限；`mode: "any"` 时可表达历史命令命中任一项即可。

## 教师端交互

步骤编辑器在 verification JSON 前展示中文摘要卡片：完成模式、检查项类型、候选命令或路径，以及“任一即可/全部需要/顺序不限”等判断方式。JSON 编辑保留在高级折叠区域，方便继续精修。

学生准入区保留单个录入，新增 TXT 批量导入。文件格式为 `学号,姓名`，每行一条；重复学号更新姓名并恢复 active 状态，错误行跳过并返回警告。

AI 识别文档在请求期间显示旋转加载、分析文案和轻量进度条，避免教师误以为按钮无响应。

实验配置的四个阶段保留标签页能力，但升级为带序号、图标和简短说明的步骤轨道。实验库列表设置最大高度，默认只展示约 8 个实验，其余滚动查看。

## 测试

后端新增 pytest 覆盖：

- 批量导入学生名单会创建新学生、更新已有学生、恢复 active，并报告重复/错误行。
- `command_match` 多个 commands 是候选关系。
- `command_set` 能在本步骤历史命令中判断“全部出现且不限顺序”。

前端通过 TypeScript/Vite 生产构建和浏览器验证确认 UI 可用。
