# 教师端实验配置管理设计

## 背景

教师端当前已经具备实验导入、基础信息编辑、步骤 JSON 编辑、容器 JSON 编辑、保存配置、构建镜像并发布的闭环。但现有界面更像“编辑当前实验”，不适合管理多个实验。短期目标是把教师端收敛成“实验配置工作台”，重点解决实验的增删、切换、状态管理和配置校验，不扩展课堂监控、学生进度统计或报告管理。

## 目标

1. 左侧提供实验列表，教师可以搜索、筛选并点击切换实验。
2. 支持添加实验，包括空白新建、复制当前实验、从 Markdown/TXT 导入。
3. 支持删除实验，但采用停用/归档方式，避免破坏历史会话和报告。
4. 引入清晰的实验状态：草稿、已发布、已停用。
5. 保留现有高级 JSON 配置能力，同时改善保存校验和状态反馈。
6. 学生端只展示已发布实验，避免草稿实验进入学生实训入口。

## 非目标

1. 不做课堂实时监控。
2. 不做学生完成进度看板。
3. 不做报告列表和成绩统计。
4. 不在第一版实现完整步骤可视化编辑器。
5. 不硬删除实验数据库记录或关联历史数据。

## 推荐方案

采用资源管理器式布局：

- 顶部：保留品牌、教师端标题、返回学生端入口和全局状态提示。
- 左侧：实验库列表，承担搜索、筛选、新建、复制、切换、停用入口。
- 右侧：配置详情，继续承载基础信息、文本导入、容器配置、步骤配置、构建发布。

这个方案在现有 React 教师页和 FastAPI 实验接口上演进，改动边界清楚，能快速提升多实验管理体验。

## 信息架构

左侧实验库包含：

- 搜索框：按实验名称、实验 ID、镜像名过滤。
- 状态筛选：全部、草稿、已发布、已停用。
- 实验条目：显示实验名称、实验 ID、状态、步骤数、镜像名。
- 操作区：新建实验、复制当前实验。

右侧配置详情包含：

- 基础信息：实验 ID、实验名称、系统类型、Docker 镜像、实验目标、实验状态。
- 文本导入：沿用粘贴文本和上传 Markdown/TXT 文件生成草稿。
- 容器配置：保留 JSON 编辑。
- 步骤配置：保留 JSON 编辑，并在保存前做结构校验。
- 构建发布：沿用当前镜像构建、日志、Dockerfile 预览和构建状态。

## 状态模型

实验状态使用三个面向教师的状态：

- draft：草稿。教师可编辑，学生端不可见。
- published：已发布。学生端可见，可用于创建实训会话。
- inactive：已停用。教师端可查看和恢复，学生端不可见。

兼容现有数据：

- 现有 active 状态按 published 处理。
- 现有 inactive 状态保持已停用。
- 保存新实验时默认状态为 draft，教师明确发布后才进入学生端。

## 关键交互

### 切换实验

教师点击左侧实验条目后，右侧加载对应配置。若当前配置有未保存修改，切换前提示确认，避免误丢改动。

### 新建实验

点击新建后创建空白草稿：

- experiment_id 默认生成 new-experiment 或基于名称生成。
- name 为空或“未命名实验”。
- system 默认 openEuler。
- container_spec 使用现有默认源配置。
- steps 默认为空数组。
- status 默认为 draft。

### 复制实验

复制当前实验时：

- 复制基础信息、目标、容器配置和步骤。
- 新 ID 自动追加 copy 后缀，名称追加“副本”。
- 状态重置为 draft。
- 构建记录不复制。

### 删除实验

删除按钮执行停用：

- 将状态改为 inactive。
- 左侧列表根据筛选决定是否继续显示。
- 学生端立即不再显示该实验。
- 已有关联会话、日志、报告不受影响。

### 发布实验

已发布状态代表学生可选。发布前必须通过校验：

- 实验 ID 非空且格式稳定。
- 实验名称非空。
- 镜像名非空。
- 步骤 JSON 是数组。
- 每个步骤有 id、title，并至少有 goal/instructions/success_criteria 中的关键说明。
- 容器配置 JSON 合法。

## 数据流

1. 教师端进入页面后调用管理员实验列表接口，加载全部状态实验。
2. 左侧列表基于本地搜索词和状态筛选展示。
3. 点击实验后，将 experiment.task_config 拆成基础表单、容器 JSON、步骤 JSON。
4. 保存时先做前端校验，再调用现有保存实验接口。
5. 停用时调用现有删除接口，后端执行软删除。
6. 发布后学生端接口只返回 published 或兼容的 active 实验。

## API 影响

优先复用现有接口：

- GET /api/admin/experiments：教师端加载全部实验。
- POST /api/admin/experiments：保存新实验或更新实验配置。
- DELETE /api/admin/experiments/{experiment_id}：软删除为 inactive。
- POST /api/admin/experiments/import：文本导入。
- POST /api/admin/experiments/import-file：文件导入。
- POST /api/admin/experiments/build：构建并保存发布。

需要调整的行为：

- GET /api/experiments 只返回 published，并兼容旧 active。
- 新建实验默认 draft。
- 构建成功后将目标实验状态设为 published，或保留教师在表单中选择的发布状态，但不能把 inactive 实验意外发布。

## 错误处理

- JSON 解析错误在对应编辑区附近展示，不只放到全局状态。
- 保存失败时保留草稿内容，不重置表单。
- 删除/停用前显示确认，确认文案说明不会删除历史记录。
- 构建中禁用会影响构建输入的字段，避免构建参数在过程中变化。
- 切换实验时检测未保存修改，提示保存、放弃或取消切换。

## 测试策略

后端测试：

- 管理员列表返回全部状态实验。
- 学生端列表只返回 published 和兼容 active。
- 删除实验只更新 inactive，不删除会话。
- 保存 draft/published/inactive 状态能正确持久化。

前端测试或手动验证：

- 左侧列表能搜索、筛选、切换。
- 新建实验生成草稿并可保存。
- 复制实验不会覆盖原实验。
- 停用实验后学生端不显示。
- JSON 错误和必填项错误能阻止发布。
- 构建成功后列表和详情状态同步刷新。

## 实施边界

第一版不引入新的大组件体系，只在现有教师页基础上拆出必要的局部组件：

- ExperimentSidebar：实验列表、搜索、筛选、新建、复制。
- ExperimentEditor：右侧配置详情。
- ValidationSummary：保存和发布前的校验提示。

这样既能控制文件复杂度，也方便后续再把步骤 JSON 编辑升级成可视化步骤编辑器。
