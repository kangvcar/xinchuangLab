## 三、进阶知识点

### 3.1 分组捕获与反向引用

#### 3.1.1 捕获组 `( )`

用圆括号 `()` 将模式分组，并**捕获**匹配内容供后续使用。

```bash
# 示例：提取年月日
$ echo "2026-05-25" | grep -oP '(\d{4})-(\d{2})-(\d{2})'
2026-05-25

# 使用 Python 查看捕获内容
$ python3 -c "import re; m = re.match(r'(\d{4})-(\d{2})-(\d{2})', '2026-05-25'); print(m.groups())"
('2026', '05', '25')
```

#### 3.1.2 非捕获组 `(?: )`

如果你只需要分组但**不需要捕获**，使用 `(?:...)` 可以提升性能。

```regex
(?:https?|ftp)://       # 匹配 http:// 或 https:// 或 ftp://，但不捕获协议名
```

#### 3.1.3 反向引用 `\1`, `\2` ...

在正则表达式内部引用之前捕获的内容。

```bash
# 匹配成对的 HTML 标签
$ echo "<div>内容</div>" | grep -oP '<(\w+)>.*?</\1>'
<div>内容</div>

# 匹配重复单词（如 "the the"）
$ echo "the the cat" | grep -oP '\b(\w+)\s+\1\b'
the the
```

> ⚠️ **注意**：反向引用在替换操作中极为有用，例如将 `名 姓` 改为 `姓, 名`。

### 3.2 贪婪与非贪婪匹配

| 量词 | 模式 | 说明 |
|------|------|------|
| `.*` | 贪婪 | 尽可能匹配最长字符串 |
| `.*?` | 非贪婪（懒惰） | 尽可能匹配最短字符串 |
| `.+?` | 非贪婪 | 至少匹配1个，但尽可能短 |
| `{n,m}?` | 非贪婪 | 匹配 n 到 m 次，优先取最少 |

```bash
# 贪婪示例（默认）
$ echo "<p>段落1</p><p>段落2</p>" | grep -oP '<p>.*</p>'
<p>段落1</p><p>段落2</p>    # 匹配了整个字符串！

# 非贪婪示例
$ echo "<p>段落1</p><p>段落2</p>" | grep -oP '<p>.*?</p>'
<p>段落1</p>
<p>段落2</p>
```

> 🔑 **核心口诀**：贪婪"多吃"，非贪婪"少吃"。当匹配结果"过长"时，尝试在量词后加 `?`。

---

### 3.3 零宽断言（Lookaround）

零宽断言匹配一个**位置**，而非字符。它们不会消耗字符，只判断"前后是什么"。

| 断言 | 名称 | 含义 | 示例 |
|------|------|------|------|
| `(?=...)` | 正向前瞻 | 后面跟着... | `\w+(?=\.)` 匹配句号前的单词 |
| `(?!...)` | 负向前瞻 | 后面**不是**... | `\d{3}(?!px)` 匹配后面不接 "px" 的数字 |
| `(?<=...)` | 正向后顾 | 前面是... | `(?<=\$)\d+` 匹配 `$` 后的金额数字 |
| `(?<!...)` | 负向后顾 | 前面**不是**... | `(?<!\d)\d{4}(?!\d)` 匹配独立的4位数（如年份） |

```bash
# 正向前瞻：匹配后面跟着 "元" 的数字
$ echo "价格是 100 元" | grep -oP '\d+(?= 元)'
100

# 正向后顾：匹配 $ 后的价格
$ echo "Price: $99.50" | grep -oP '(?<=\$)[\d.]+'
99.50

# 负向后顾：匹配不以 "TODO:" 开头的行（在 vim/sed 中常用）
$ cat notes.txt | grep -P '^(?!TODO:).*'
```

> 💡 **对比**：
> - `\d+(?=元)` 只返回数字 `100`
> - `\d+元` 返回 `100元`
>
> 零宽断言不消耗匹配位置，因此后续匹配仍从同一位置开始。

---

### 3.4 原子组与占有量词（性能优化）

在复杂正则或回溯严重的场景（如 .* 匹配长文本），可以使用原子组避免不必要的回溯。

| 语法 | 说明 | 支持环境 |
|------|------|----------|
| `(?>...)` | 原子组：匹配成功后不回溯 | PCRE、Perl、Java、.NET |
| `*+` / `++` / `?+` | 占有量词：类似原子组的效果 | PCRE、Java、.NET |

```regex
# 原子组示例：快速失败
(?>\d+)abc    # 如果 \d+ 匹配了 "123" 但后面不是 "abc"，不会回溯让出数字

# 对比：非原子组会回溯
(\d+)abc     # "123xyz" 失败时，\d+ 会尝试只匹配 "12"，再看是否 "abc"
```

> 📌 **适用场景**：输入验证、长文本解析、防止 ReDoS（正则表达式拒绝服务攻击）。

---

### 3.5 注释与模式修饰符

在支持 `x`（VERBOSE）模式的语言中（如 Python），可以给正则添加注释和换行，提升可读性。

```python
import re

pattern = re.compile(r'''
    (?P<protocol>https?)://    # 协议：http 或 https
    (?P<host>[\w.-]+)          # 主机名
    (?::(?P<port>\d+))?        # 可选端口号
    (?P<path>/.*)?             # 可选路径
''', re.VERBOSE)

url = "https://example.com:8080/api/v1"
m = pattern.match(url)
print(m.groupdict())
```

## 四、实战练习

### 关卡 1：日志时间戳提取

**任务**：从系统日志中提取日期时间部分。

```text
输入样例：
[2026-05-25 14:32:01] INFO: Service started
[2026-05-25 14:32:05] ERROR: Connection timeout
```

**目标**：编写正则，仅提取 `2026-05-25 14:32:01` 这样的时间戳。

<details>
<summary>参考答案</summary>

```regex
\[([\d\-:\s]+)\]
```

或更精确：

```regex
\[(\d{4}-\d{2}-\d{2}\s+\d{2}:\d{2}:\d{2})\]
```

</details>

### 关卡 2：HTML 属性提取

```html

<div class="container main active" id="wrapper">
<span class="badge" data-id="123">
```

**目标**：提取 `container main active` 和 `badge`。

<details>
<summary>参考答案</summary>

或使用非贪婪：

### 关卡 3：密码强度验证

**任务**：验证密码是否同时包含大写字母、小写字母、数字，且长度 8~20 位。

**要求**：使用**零宽断言**实现，不在匹配中消耗字符。

<details>
<summary>参考答案</summary>

```regex
^(?=.*[A-Z])(?=.*[a-z])(?=.*\d)[A-Za-z\d]{8,20}$
```

**解释**：
- `(?=.*[A-Z])` — 正向前瞻：后面有大写字母
- `(?=.*[a-z])` — 正向前瞻：后面有小写字母
- `(?=.*\d)` — 正向前瞻：后面有数字
- `[A-Za-z\d]{8,20}` — 实际匹配 8~20 位字母数字

</details>

### 关卡 4：千分位数字格式化

**任务**：将长数字转换为千分位格式。

```text
输入：1234567890
输出：1,234,567,890
```

**提示**：使用**后顾断言**在正确的位置插入逗号。

<details>
<summary>参考答案（Python）</summary>

```python
import re

num = "1234567890"
# 从右向左，每 3 位一组
result = re.sub(r'(?<=\d)(?=(?:\d{3})+$)', ',', num)
print(result)  # 1,234,567,890
```

**解释**：
- `(?<=\d)` — 前面是数字
- `(?=(?:\d{3})+$)` — 后面是 3 的倍数个数字直到结尾
- 两者之间的"位置"就是应该插入逗号的位置

</details>

### 关卡 5：Markdown 链接提取

**任务**：从 Markdown 文本中提取链接文本和 URL。

```markdown
输入样例：
[OpenEuler](https://openeuler.org) 是开源操作系统。
查看 [官方文档](https://docs.openeuler.org "文档首页")。
```

**目标**：提取出 `(OpenEuler, https://openeuler.org)` 等。

<details>
<summary>参考答案</summary>

```regex
\[([^\]]+)\]\(([^\s")]+)(?:\s+"[^"]*")?\)
```

或使用命名捕获组：

```regex
\[(?P<text>[^\]]+)\]\((?P<url>[^\s")]+)
```

</details>

## 五、综合挑战

### 挑战：Apache 日志分析器

给定一段 Apache/Nginx 访问日志：

```log
192.168.1.1 - - [25/May/2026:14:32:01 +0800] "GET /api/users HTTP/1.1" 200 1234 "https://example.com" "Mozilla/5.0"
10.0.0.5 - - [25/May/2026:14:32:05 +0800] "POST /login HTTP/1.1" 302 0 "-" "curl/7.68.0"
```

**要求**：

1. 用**一条正则表达式**提取出：IP、时间、方法、路径、状态码、User-Agent。
2. 使用**命名捕获组**给每个字段命名。
3. 确保 User-Agent 可能包含空格也能正确匹配。

<details>
<summary>参考答案</summary>

```regex
^(?P<ip>[\d.]+)\s+\S+\s+\S+\s+\[(?P<time>[^\]]+)\]\s+"(?P<method>\w+)\s+(?P<path>\S+)\s+[^"]*"\s+(?P<status>\d+)\s+\d+\s+"[^"]*"\s+"(?P<ua>[^"]*)"
```

**Python 完整示例**：

```python
import re

log_line = '192.168.1.1 - - [25/May/2026:14:32:01 +0800] "GET /api/users HTTP/1.1" 200 1234 "https://example.com" "Mozilla/5.0"'

pattern = re.compile(
    r'^(?P<ip>[\d.]+)\s+\S+\s+\S+\s+\[(?P<time>[^\]]+)\]\s+'
    r'"(?P<method>\w+)\s+(?P<path>\S+)\s+[^"]*"\s+'
    r'(?P<status>\d+)\s+\d+\s+"[^"]*"\s+"(?P<ua>[^"]*)"'
)

m = pattern.match(log_line)
if m:
    print(m.groupdict())
```

</details>

## 六、常见问题排错

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| 匹配结果过长 | 贪婪量词 `.*` 或 `.+` 过度匹配 | 改用非贪婪 `.*?` 或限定字符集 `[^>]*` |
| 多行文本匹配失败 | `.` 默认不匹配换行符 | 开启 DOTALL 模式（`re.DOTALL` / `(?s)`） |
| 中文/Unicode 匹配异常 | 未启用 Unicode 支持 | Python 中加 `re.UNICODE` 或使用 `\w`（Python3 默认支持） |
| 分组太多，编号混乱 | 捕获组过多 | 改用非捕获组 `(?:...)` 或命名捕获组 `(?P<name>...)` |
| 正则执行极慢 | 灾难性回溯（Catastrophic Backtracking） | 使用原子组 `(?>...)` 或占有量词 `++`，限制输入长度 |
| `grep -P` 报错 | 系统 grep 不支持 PCRE | 改用 `perl -ne` 或 `pcregrep`，或使用 Python |

```bash
# perl（完整 PCRE 支持）
perl -nE 'say $1 if /(\d{4}-\d{2}-\d{2})/' file.txt

# Python 单行处理
python3 -c "import re,sys; [print(re.findall(r'\d{4}-\d{2}-\d{2}', l)) for l in sys.stdin]"
```

## 八、实验总结

| 进阶技能 | 掌握要点 |
|----------|----------|
| 捕获组 | `()` 提取，`(?:)` 不提取，`(?P<name>)` 命名 |
| 反向引用 | `\1` 引用第一个捕获组，用于匹配成对结构 |
| 贪婪/非贪婪 | 默认贪婪，加 `?` 变懒惰，控制匹配长度 |
| 零宽断言 | `(?=)` `(?!)` `(?<=)` `(?<!)` 匹配位置，不消耗字符 |
| 原子组 | `(?>)` 防止回溯，优化性能 |
| 注释模式 | `re.VERBOSE` 让正则可读性大幅提升 |
